# プロトタイプ設計書 p0.1

## 1. 本書について

本書は circularnodes の最初のプロトタイプ **p0.1** の設計を定義する。製品としての仕様は [概要仕様書](../overview.md) / [機能仕様書](../functional-spec.md) / [技術仕様書](../technical-spec.md) に従うが、本書ではそのうち p0.1 で実装する範囲のみを扱う。

- 版数: p0.1 (draft)
- 最終更新日: TODO
- 位置づけ: 使い捨て前提ではなく、`geometry` 層はそのまま本実装へ引き継ぐ

## 2. 目的

p0.1 で確かめたいことは次の 3 点である。

| # | 検証したいこと | 判断方法 |
| --- | --- | --- |
| V-1 | 「正方形＋内接円」のグリッド上で領域を塗るという操作で、実際に字が作れるか | 参考字形（`../img/ref-image.png`）の文字を再現できる |
| V-2 | 1 セル 5 領域という分割粒度が過不足ないか | 再現の過程で「塗り分けたいのに塗れない」箇所が出ないか |
| V-3 | ドラッグによる連続描画の操作感が成立するか | 意図しない領域を塗ってしまわないか |
| V-4 | 書き出した SVG が後工程で使えるか | Illustrator で開き、パスとして編集できる |

上記以外（永続化、設定 UI、性能）は p0.1 の検証対象外とする。

### 3.3 操作方式の決定

ペン／消しゴムのツール切替は設けず、**ストローク単位のモード決定**とする。

1. ポインタダウンした領域が「未描画」なら、そのストロークは**塗りモード**
2. ポインタダウンした領域が「描画済み」なら、そのストロークは**消しモード**
3. ドラッグ中に通過した領域へ、決定したモードを適用する（同一領域を再通過してもトグルしない）

これによりツール UI も Undo も無しで塗り・消しの両方が行える。[機能仕様書](../functional-spec.md) 6.2 の未決事項に対する p0.1 での暫定解であり、本実装での採否は検証後に判断する。

単一画面。最上部にメニューバーを固定し、その下にキャンバスを中央配置する。

+------------------------------------------+
|                                          |
|        +------------------------+        |
|        |                        |        |
|        |     canvas             |        |
|        |  (グリッド＋描画結果)     |        |
|        |                        |        |

+------------------------------------------+

メニューバーの構成と挙動は [機能仕様書](../functional-spec.md) 13 章、ステータスバーは同 14.5 に従う。ステータスバー左の固定テキストは、キーボードから到達できない操作（ドラッグによる塗り／消し）のみに絞る。他の操作はメニュー上のショートカット表記で足りる。

メニューバーとステータスバーの寸法・配色は Canvas の描画に関わらないため、`config.ts` ではなく `index.html` の CSS に置く。

## 7. データモデル

[技術仕様書](../technical-spec.md) 4.2 の `RegionId` を用いる。状態保持は**密配列**とし、キャンバスサイズの変更時に配列を作り直して既存の描画を移し替える。

```ts
type RegionKind = 'C' | 'NW' | 'NE' | 'SW' | 'SE';

const KIND_ORDER: RegionKind[] = ['C', 'NW', 'NE', 'SW', 'SE'];

type RegionId = { col: number; row: number; kind: RegionKind };

/** 実行時に変わるグリッドの設定。ノード形状もここに持つ（ドキュメントの属性） */
const grid = { columns: DEFAULT_COLUMNS, rows: DEFAULT_ROWS, shape: DEFAULT_SHAPE };

/** 描画状態。0 = 未描画, 1 = 描画済み。サイズ変更時に作り直す */
let filled = new Uint8Array(grid.columns * grid.rows * KIND_ORDER.length);

const indexOf = (r: RegionId): number =>
  (r.row * grid.columns + r.col) * 5 + KIND_ORDER.indexOf(r.kind);
```

グリッドの設定が実行時に変わるため、`geometry` の範囲判定と形状生成はグリッドを引数で受け取る（`hitTest(gx, gy, grid)`）。`geometry` を状態から独立させたまま保つための措置である。

ノード形状は領域の**形**にのみ効き、分割数・識別子・隣接関係を変えない。したがって形状を変えても `filled` は作り直さない。

サイズ変更時は新しい配列を確保し、新旧のセル範囲が重なる部分だけを移し替える。縮小で範囲外になる領域の描画は失われる（機能仕様書 8.3）。

エディタ状態は次のみ。

```ts
type EditorState = {
  /** 現在のストロークのモード。null ならドラッグ中でない */
  strokeMode: 'fill' | 'erase' | null;
  /** 直前のポインタ位置（補間に使う）。グリッド座標 */
  lastPoint: { gx: number; gy: number } | null;
  showGuide: boolean;
  /** 表示倍率。描画内容には影響しない */
  zoom: number;
  showHighlight: boolean;
  /** ポインタが乗っている領域。キャンバス外なら null */
  hoverRegion: RegionId | null;
};
```

パンの待機・実行状態は文書の内容ではなく一時的な入力状態のため、`EditorState` には持たせず `input.ts` の内部に閉じる。ポインタの形はステージに付けるクラスで切り替える。

## 8. 幾何処理

`src/geometry.ts`。UI・描画に依存しない純粋関数として実装する。

座標変換は「スクリーン座標 → （倍率で割る）→ ワールド座標 → （`CELL_SIZE` で割る）→ グリッド座標」の順とする。倍率は描画とヒットテストの双方に効くため、変換を 1 か所にまとめる。

### 8.1 ヒットテスト

[技術仕様書](../technical-spec.md) 7.2 の手順をそのまま実装する。

```ts
function hitTest(gx: number, gy: number): RegionId | null;
```

- グリッド外は `null`
- 円周上（中心からの距離がちょうど `0.5`）は円領域に含める

### 8.2 ドラッグの補間

p0.1 では**等間隔サンプリング**とする。前回位置と今回位置の間を、グリッド座標で `0.25` セル刻み（＝最小領域を跨がない程度）に分割し、各点で `hitTest` を呼んで通過領域を集める。

DDA による厳密な走査は p0.1 では行わない。取りこぼしが実用上問題になるかを V-3 で確認し、必要なら本実装で置き換える。

**実装時の変更**: 刻み幅は `0.25` では不足したため `0.1`（`SAMPLE_STEP`）とした。隅領域は円との接点付近で細くなり、辺の中点近くを横切るドラッグでは幅が `0.2` セルを下回る。`0.25` 刻みではこれを飛び越して取りこぼす。

### 8.3 領域の輪郭パス

`geometry` が輪郭を「直線・円弧・3 次ベジェ」からなるパスとして返し、`render.ts` と `export.ts` がそれぞれ Canvas 命令と SVG のパス文字列に変換する（[技術仕様書](../technical-spec.md) 6.2）。

| ノード形状 | 返す形 |
| --- | --- |
| 既定（正円） | 従来どおり円・円弧。近似なし |
| `0`（45 度の正方形） | 直線のみ。近似なし |
| それ以外 | 四分スーパー楕円を 3 次ベジェで近似したパス |

四分曲線は第 1 象限のものを 1 つ生成し、回転・反転して 4 象限ぶんと隅領域に使い回す。

## 9. 描画処理

毎フレーム全面再描画とする（p0.1 のグリッドサイズなら差分描画は不要）。

描画順:

1. 背景を塗りつぶす
2. `filled` を走査し、描画済み領域を塗る
3. `showGuide` が真なら、正方形グリッド線を描く
4. `showGuide` が真なら、内接円を描く
5. `showHighlight` が真で、ポインタが領域に乗っていれば、その輪郭を強調色で描く

再描画のトリガは状態変更時のみ（`requestAnimationFrame` で 1 フレームに 1 回に束ねる）。常時ループは回さない。

ハイライトの対象はポインタの移動のたびに求めるが、再描画は対象の領域が変わったときだけ行う。

## 10. 入力処理

`src/input.ts`。Pointer Events を使用する。

| イベント | 処理 |
| --- | --- |
| `pointerdown` | ヒットテスト → 対象領域の現在値から `strokeMode` を決定 → 適用 → `setPointerCapture` |
| `pointermove` | ポインタが乗っている領域を更新する。`strokeMode` が非 null なら補間して通過領域へ適用 |
| `pointerleave` | ポインタが乗っている領域を `null` に戻す |
| `pointerup` / `pointercancel` | `strokeMode` と `lastPoint` を `null` に戻す |
| `keydown` (`g`) | `showGuide` を反転 |
| `keydown` (`p`) | PNG を書き出す（11 章） |
| `keydown` (`s`) | SVG を書き出す（11 章） |
| `keydown` (`n`) | キャンバスサイズ変更ダイアログを既定サイズで開く。決定でその大きさの空のキャンバスにする |
| `keydown` (`Escape`) | 開いているメニューを閉じる。ダイアログが開いているときは `<dialog>` 側が閉じる |
| `wheel` (`⌘` または `Ctrl`) | 倍率を変える。ポインタ位置を保つようステージのスクロール量を補正する。`preventDefault` でブラウザのページズームを抑止するため、リスナは `passive: false` で登録する |
| `keydown` / `keyup` (`Space`) | パンの待機状態を切り替える。押している間はブラウザ既定のスクロールを `preventDefault` で抑える |
| `pointerdown` (パン待機中) | ステージのスクロール量の変更としてドラッグを扱う。キャンバスの描画ハンドラへ渡さないため、ステージでキャプチャ段階に受けて伝播を止める |

キャンバス外でポインタを離した場合に備え、`setPointerCapture` を使う。

## 11. 書き出し

検証 V-4 のため、p0.1 でも書き出しを実装する。オプション UI は持たず、キー操作で即座にダウンロードする。

### 11.1 共通仕様

- ガイド（グリッド線・内接円）は出力に含めない。画面の `showGuide` の状態に関わらず、**描画済み領域のみ**を出力する
- 出力範囲はグリッド全体（`COLUMNS × CELL_SIZE` × `ROWS × CELL_SIZE`）。余白は付けない
- 背景は透過とする。塗り色は `COLOR_FILL` をそのまま用いる
- ファイル名は `circularnodes-<timestamp>.png` / `.svg`
- ダウンロードは `Blob` → `URL.createObjectURL` → `<a download>` のクリックで行う

### 11.2 PNG

画面のキャンバスをそのまま使わず、オフスクリーンの `<canvas>` にガイド抜きで再描画してから `toBlob('image/png')` で取り出す。

解像度はグリッドの実寸（`CELL_SIZE` 基準の 1 倍）とする。倍率指定は p0.1 では持たない。

### 11.3 SVG

描画済み領域を 1 つずつ要素として直列化する。パスの結合は行わない（[機能仕様書](../functional-spec.md) 11 章の未決事項）。

| 領域 | 出力 |
| --- | --- |
| `C` | `<circle cx cy r>` |
| `NW` / `NE` / `SW` / `SE` | `<path d="M … L … A r r 0 0 0 … Z">`（円弧は `A` コマンドで保持） |

```svg
<svg xmlns="http://www.w3.org/2000/svg" width="..." height="..." viewBox="0 0 ... ...">
  <g fill="#000">
    <circle cx="24" cy="24" r="24"/>
    <path d="M 0 0 L 24 0 A 24 24 0 0 0 0 24 Z"/>
  </g>
</svg>
```

- 座標は `CELL_SIZE` を乗じたワールド座標で出力する
- 円弧のフラグ（`large-arc` / `sweep`）は隅の向きごとに固定値となるため、`geometry` 側に定数として持つ
- 隣接する領域は輪郭を共有するが、個別パスのままにする。Illustrator 側でパスファインダによる合体が必要になる点を V-4 で確認する

### 11.4 実装の置き場所

`src/export.ts`。塗り領域の形状定義は `geometry.ts` と共有し、Canvas 命令と SVG パス文字列の双方をそこから生成する。

## 12. ファイル構成

```
circularnodes/
├── index.html
├── package.json
├── tsconfig.json
├── vite.config.ts
└── src/
    ├── main.ts        # 初期化、イベント配線
    ├── config.ts      # 定数
    ├── types.ts       # RegionId など
    ├── geometry.ts    # 座標変換・ヒットテスト・補間
    ├── state.ts       # filled / EditorState と更新関数
    ├── render.ts      # Canvas への描画
    ├── actions.ts     # メニューとショートカットが共有するコマンド
    ├── menu.ts        # メニューバーの生成と開閉
    ├── dialog.ts      # キャンバスサイズ変更ダイアログ
    ├── shape-dialog.ts # ノード形状変更ダイアログ
    ├── slider.ts      # スライダー（吸着つき）
    ├── statusbar.ts   # ステータスバー（操作説明・ズーム）
    ├── export.ts      # PNG / SVG 書き出し
    └── input.ts       # Pointer / Key ハンドラ
```

[技術仕様書](../technical-spec.md) 3.2 のディレクトリ構成のうち、p0.1 では `io` を書き出しのみの `export.ts` に縮め、各層を 1 ファイルずつに圧縮した形とする。

メニューとショートカットは同じ操作への 2 つの入口であるため、実行内容は `actions.ts` に集約し、`menu.ts` と `input.ts` の双方がこれを呼ぶ。

スライダーを自前で持つ（`slider.ts`）のは、ネイティブの `<input type="range">` ではドラッグ中につまみの位置がポインタに固定され、値を吸着させても描画が追従しないためである（機能仕様書 17.5）。
