### 2.1 描画方式の比較検討

本アプリの描画対象は「正方形と円弧で構成された少数の図形の集合」であり、自由曲線やラスタのブラシは扱わない。

| 方式 | 利点 | 欠点 | 判断 |
| --- | --- | --- | --- |
| SVG | 領域を `<path>` として宣言的に配置できる。ヒットテストを DOM のイベントに任せられる。SVG 書き出しがそのまま行える | 領域数（`columns × rows × 5`）が増えると DOM ノードが増え、描画・更新が重くなる | 不採用 |
| Canvas 2D | 領域数が増えても描画コストが安定する。`arc()` で円弧をそのまま描ける | ヒットテストを自前で実装する必要がある（7.2 の解析的判定で対応可能） | **採用** |
| WebGL | 大規模グリッドでも高速 | 円弧の描画・アンチエイリアスの実装コストが見合わない | 不採用 |

**Canvas 2D を採用する。** 決め手は次の 2 点。

- ヒットテストは 7.2 のとおり中心からの距離を 1 回計算するだけで済むため、SVG が持つ「DOM にヒットテストを任せられる」利点がほとんど効かない
- 領域数はグリッドサイズに比例して増えるため（`columns × rows × 5`）、DOM ノード数が増えない方式のほうが上限を気にせずに済む

SVG は描画方式としては採らないが、書き出し形式としては用いる（9 章）。領域の形状定義を `geometry` に持たせ、Canvas の描画命令と SVG のパス文字列を同じ定義から生成する。

## 4. データモデル

### 4.1 座標系

- **グリッド座標**: 原点を左上のセル `(col=0, row=0)` の左上頂点に置き、右方向を +x、下方向を +y とする。単位はセル 1 個分。
- **ワールド座標**: グリッド座標に `cellSize` を乗じた値。
- **スクリーン座標**: ワールド座標にズーム倍率とパンのオフセットを適用した値。変換行列は `render` が保持する。

### 4.2 領域の表現

1 セルは内接円によって 5 領域に分割される（[機能仕様書](./functional-spec.md) 3.2）。領域は幾何形状を実体として持たず、**セル座標 + 領域種別**の組で一意に識別する。

```ts
/** セル内の領域種別 */
type RegionKind = 'C' | 'NW' | 'NE' | 'SW' | 'SE';

/** 領域の識別子 */
type RegionId = {
  col: number;
  row: number;
  kind: RegionKind;
};
```

領域の実形状（円、あるいは辺と円弧で囲まれた隅）は `geometry` が `RegionId` から都度導出する。これにより `cellSize` 変更時に保存データを作り直す必要がない。

### 4.3 主要な型

```ts
// TODO: 実装に合わせて更新すること

  /** ノード形状 t（F-13）。0.5 で正円 */
  shape: number;

/** 1 文字分の作字データ */
type Document = {
  version: number;
  grid: GridConfig;
  /** 描画済みの領域のみを保持する（未描画は集合に含めない） */
  filled: Set<RegionKey>; // RegionKey = `${col},${row},${kind}`
};
```

| 方式 | 利点 | 欠点 |
| --- | --- | --- |
| 疎集合（`Set<RegionKey>`） | グリッド変更に強い。保存サイズが小さい | 走査順が保証されない |
| 密配列（`Uint8Array(columns * rows * 5)`） | インデックス計算が O(1)、描画ループが速い | グリッドのリサイズ時に再構築が必要 |

p0.1 では密配列を採り、キャンバスサイズの変更時に配列を作り直して、新旧のセル範囲が重なる部分の状態を移し替えている。移し替えのコストはサイズ変更時のみに発生し、描画のたびのコストには影響しない。

### 4.4 ノード形状

中心領域は L^p ノルムの単位球（スーパー楕円）とし、指数は `p = 1 / (1 - shape)` で求める（機能仕様書 17.2）。

```ts
const exponent = (shape: number): number => 1 / (1 - shape);
```

曲線は `shape` の値によらずセルの 4 辺の中点を通る。したがって領域の分割数・識別子・隣接関係は `shape` に依存せず、`shape` を変えても保存済みの描画状態はそのまま有効である。`shape` は領域の**形**にのみ効く。

### 4.5 領域インデックス

密配列を採る場合のインデックス規則:

```
index = (row * columns + col) * 5 + kindOrder
kindOrder: C=0, NW=1, NE=2, SW=3, SE=4
```

## 5. 状態管理

- ストアの構造: `Document` + エディタ状態（現在のツール、ズーム、パン、ホバー中の領域）を分離して保持する。
- 更新フロー: 入力イベント → コマンド生成 → `Document` 更新 → 再描画。
- Undo/Redo: 1 ストローク（ポインタダウン〜アップ）を 1 コマンドとして記録する。コマンドは「トグルした領域 ID の集合」を保持すればよく、スナップショットより軽い。

### 6.2 領域のパス生成

領域の輪郭は、ノード形状（4.4）に応じて次のように生成する。

| `shape` | 中心領域 `C` | 隅領域 |
| --- | --- | --- |
| 0.5（正円） | 中心 `(col + 0.5, row + 0.5)`、半径 `0.5` の円 | 頂点から 2 つの辺中点へ伸ばし、半径 `0.5` の円弧（内側に凹）で閉じた図形 |
| 0（45 度の正方形） | 4 辺の中点を結ぶ直線 | 頂点と 2 つの辺中点を結ぶ三角形 |
| それ以外 | 四分スーパー楕円 4 つ | 頂点 → 辺中点 → 四分スーパー楕円 → 閉じる |

既定の正円は `arc()` / `A`、`shape = 0` は直線で、いずれも近似なしに描ける。それ以外は 3 次ベジェで近似する。

四分曲線の近似は、`θ ∈ [0, π/2]` を等分し、各区間の端点・単位接線・中点から制御点を解いて求める。パラメータ微分は `shape > 0.5` のとき端点で発散するため、微分そのものではなく**単位接線**（端点では解析的な極限値）を用いる。

- `shape > 0`（`p > 1`）: 辺中点での接線は辺と平行
- `shape = 0`（`p = 1`）: 中点は 45 度の角
- `shape < 0`（`p < 1`）: 中点は尖点。接線は辺と垂直

したがって輪郭は、円弧・直線・3 次ベジェのいずれかからなるパスとして表す。Canvas は `arc` / `lineTo` / `bezierCurveTo`、SVG は `A` / `L` / `C` に対応する。

### 6.3 パフォーマンス方針

- 再描画の粒度: 表示範囲の全面再描画。キャンバスは表示領域（ステージ）と同じ大きさだけを持ち、グリッドの原点との差を描画変換の平行移動で与える
- 描画対象の絞り込み: 表示範囲に入るセルだけを走査する。所要時間がグリッドの大きさによらず一定になり、描画先も画面ぶんで済む
- ズーム時の描画: 倍率を描画変換に掛け、拡大時も輪郭を保つ
- 想定する最大グリッドサイズ: 100 × 100 = 50,000 領域（機能仕様書 8.1）

## 7. 入力処理

### 7.1 対応入力

| 入力 | 扱い |
| --- | --- |
| マウス | クリックで単一領域、ドラッグで連続描画 |
| タッチ | マウスと同等。パン・ズームとの競合解決は TODO |
| ホイール | `⌘` / `Ctrl` を伴うときのみズーム（F-10）。それ以外はステージのスクロールに任せる |
| ペン | 筆圧・傾きは使用しない（領域は 2 値のため） |
| キーボード | ショートカット。`Space` は押している間パンの待機状態にする（F-11） |

マウス・タッチ・ペンは Pointer Events で一元的に扱う。

### 7.2 ヒットテスト

スクリーン座標 `(x, y)` から `RegionId` を求める手順（グリッドの大きさは実行時に変わるため、範囲判定に使う `columns` / `rows` は引数で受け取る）:

```
1. スクリーン座標 → グリッド座標 (gx, gy) に変換する
2. col = floor(gx), row = floor(gy)
3. セル内のローカル座標 (lx, ly) = (gx - col, gy - row)   // 0..1
4. 中心基準に正規化: u = |lx - 0.5| * 2, v = |ly - 0.5| * 2   // 0..1
5. u^p + v^p <= 1 なら kind = 'C'
   そうでなければ lx, ly の 0.5 との大小関係から NW / NE / SW / SE を決める
```

`p = 2`（既定の正円）では `u² + v² <= 1`、`p = 1` では `u + v <= 1` となり、いずれも冪乗を避けられる。ノード形状を変えても計算量は O(1) のままであり、空間インデックスは不要。

- 境界上（式がちょうど `1`）の扱い: 中心領域に含める。
- グリッド範囲外の座標: `null` を返し、描画を行わない。
- ドラッグ時の取りこぼし: ポインタイベントは飛び飛びに届くため、前回座標との間を線分で補間し、通過したセル・領域を列挙する。TODO: 補間の実装方式（等間隔サンプリング / DDA）を決めること。
